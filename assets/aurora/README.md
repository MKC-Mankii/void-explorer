# AURORA — 可编辑 Blender 源与游戏资产

本目录基于 [第四轮概念设计](../../concepts/aurora/README.md)，提供已实际在 Blender 4.3.2 制作、保存、重新打开和导出的低多边形飞船。

| 文件                | 用途                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `aurora.blend`      | 可编辑的米制源文件；独立机身、四个机翼、座舱、双推进器、起落架和挂点；已打包最终概念参考图 |
| `aurora.glb`        | 游戏实际加载的 glTF 2.0 二进制；全部几何和 PBR 材质内嵌，无外部贴图或压缩解码器依赖        |
| `build-aurora.py`   | 从本轮几何定义重新生成源文件并导出；会覆盖源文件中的手工编辑                               |
| `export-aurora.py`  | 从已经编辑好的 `.blend` 导出，不重建几何；检查挂点、非流形边和资产预算                     |
| `asset-report.json` | 实际导出统计及源文件、GLB 的 SHA-256                                                       |

## 编辑与复现

```bash
# 从定义重建：覆盖 aurora.blend，随后导出
blender -b --python assets/aurora/build-aurora.py

# 在 Blender 编辑并保存 .blend 后，只导出，不覆盖编辑
blender -b assets/aurora/aurora.blend --python assets/aurora/export-aurora.py

npm run build
npm test
# 游戏开发服务器运行于 5173 后
npm run test:aurora
```

源文件在 Blender 中可以继续编辑网格、边缘倒角和六种材质；不是一个只能查看的离线渲染。`AURORA` 根节点及其后代是导出范围，旁边的概念参考图不导出。脚本使用 Blender 内置网格、材质和 glTF 导出器；未安装或使用 Draco 压缩。Blender 可能打印可选 Draco 库缺失信息，实际未压缩 GLB 的导出与加载已通过检查。

继续编辑时保留命名挂点和零件元数据。若改变翼展、着陆基准、视觉中心或出口位置，还需同步 `src/ship-layout.ts` 的包络/模拟参数并重跑资产与交互检查；相机和推进焰读取导出挂点，步行阻挡仍是单独定义的粗略包络。

源文件不是手工雕刻或高模烘焙资产：它由 Python 在 Blender 内生成并保留可编辑零件。没有法线贴图、UV 烘焙、骨骼或 Blender 关键帧；起落架伸缩与推进焰由游戏按节点驱动。

## 几何取舍

- 采用一组统一三维尺寸解决概念图投影误差：名义长 18 m、后翼展 18.6 m、前翼展 12.6 m；实际含喷口环的包围盒长约 18.034 m。
- 四翼为真正独立的有厚度网格：`Wing_Fore_Port`、`Wing_Fore_Starboard`、`Wing_Aft_Port`、`Wing_Aft_Starboard`。前翼前掠、翼根高 3.4 m，后翼后掠、翼根高 2.0 m；前翼有约 8° 上反趋势。翼厚分别约 0.18 / 0.22 m，小倒角保留轮廓。
- 机身使用连续的八边截面楔形体，补全机腹；唯一座舱在舰艏后 2.8–7.7 m，外壳为不透明深青色 PBR 材质。没有建模舱内或可打开玻璃。
- 两具发动机在 x = ±1.8 m、舰艏后 13.35–18 m，两枚喷口朝后；没有翼尖发动机或额外尾鳍。
- 四个起落架和三个左舷台阶是本轮补全。脚垫在源文件地面基准 Z=0，机腹最低约 1.12 m；不可把机腹视为可站立穿行的通道。
- 左舷舱口位于前后翼根之间，预留约 1 m 纵向宽度、约 1.72 m 高的舱口区域和外部台阶。出口在左舷 x=-3.25 m、舰艏后 9.9 m；这是现有 E 键交互的空间占位，没有新增可步入内部、开门或爬梯玩法。

## 游戏坐标与挂点

Blender：X 向右舷、Y 向舰艏、Z 向上，1 单位 = 1 m，纵向中心在舰艏后 9 m。导出：X 向右舷、Y 向上、Z 向舰尾，舰艏为 Z=-9 m。游戏既有尺度为 1 单位约 10 m，因此加载根节点缩放为 `0.1`。

保留模拟器的着陆基准 0.61 游戏单位：加载场景沿局部 Y 下移 6.1 m，再乘 0.1。这样脚垫仍落在地面，既有保存的船体基准位置和姿态不需要改写。

| 节点                                 | 游戏用途                                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------- |
| `Cockpit_View`                       | 真正的驾驶舱镜头位置：源高度 3.68 m；进入舱内视角时隐藏外壳，保留现有仪表覆层 |
| `Chase_Target`                       | 机身视觉中心，源高度 2.35 m；离船后视线目标                                   |
| `Boarding_Exit`                      | 左舷出口；水平挂点映射到程序地表，眼高沿用 1.8 m                              |
| `Exhaust_Port` / `Exhaust_Starboard` | 运行时推进焰锚点；沿导出局部 +Z 喷射                                          |
| `Gear_*` / `Contact_*`               | 四套伸缩支柱和接地点；着陆后按脚点附近的程序地表作有限伸缩                    |
| `Boarding_Steps`                     | 随起落架显隐、收起的左舷台阶                                                  |

目前约 2,584 三角形、29 个网格图元、6 种材质、0 张资产贴图，GLB 163,824 字节。静态铜色、翼根与发动机顶板按材质合并；四翼保持独立。飞行中隐藏起落架和台阶，因此实际可见图元少于全展开模型。真实桌面 GPU 性能仍需实机验证。
