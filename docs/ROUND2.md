## 观察到的问题

先在基线版本运行真实浏览器交互：新游戏 → 星图选 PYRA → F 扫描 → Shift+W → 松开 Shift 继续 W → Tab 切换 → T → 保存并刷新。没有放置场景或推进模拟时间。状态证据见 [baseline.json](round2/baseline.json)，画面见 [基线截图](round2/screenshots/baseline-flight.png)。

1. 选中 PYRA，F 却写入 VESPER 的扫描记录。导航面板和执行对象不一致。
2. 松开 Shift 后仍按 W，指令速度在 0.1501 个模拟秒内从 524.076 降至 320，源于有油门时直接 clamp、无油门时才 damp。实际速度另有平滑，不能把这个指令跳变说成实际速度瞬间跳变。
3. T / 星图导航立即重写姿态，保持原速度与运动方向，导致突然转身及镜头跟随落后。
4. 保存不含目标、速度和速度向量；刷新后目标从 NIVALIS 回到 VESPER，运动归零。
5. 雷达目标点固定不动，所有屏外目标都写“在后方”。没有直观区分船头、真实运动方向和目标方位，也没有直接目标锁定。
6. 远航只有持续手动推进，缺少接近速度、ETA、航向误差和接近减速反馈。

## 实际修改

- 推进、释放加速和环境限速使用一致的加减速过程；X 制动同时抑制侧向/垂向推进。增加角速度平滑与输入速率上限，近地调平只修正横滚，避免无输入时改变船头方向。
- 追踪镜头的位置改为相对飞船的偏移，姿态单独平滑，高速下不会因世界位置插值而越来越远离飞船。星尘方向采用真实速度向量，降低密度与拖尾亮度。
- **右键**锁定准星射线首先命中的行星，**Tab**只切换选择，**T**渐进对准，星图选择接入同一套目标/转向逻辑。选中目标不改位置或瞬间重写姿态。
- **G**启用同一星系内的远航引导：逐渐转向/推进，在目标近空边界提前制动，抵达后停止引导。持续实际移动，不插值传送。手动鼠标/方向键、推进、平移或 X 可接管；T 不会自动推进。
- 对直接航路进行天体遮挡检测；被行星或恒星安全区域阻挡时说明原因，保留手动绕行能力，不自动穿过天体。暂不做多段绕障路线。
- 导航面板显示距所选行星地表的距离、航向误差、接近/远离速度、按当前接近速度估算的近空 ETA。雷达点和屏外箭头来自真实船体/相机相对方向；另示真实运动方向标记。
- F 扫描所选行星；着陆 L 仍作用于最近天体，提示中明确名称，并在成功开始着陆时同步目标。飞行中的任务提示也跟随所选目标。
- 保持版本 1 存档兼容，增加可选目标、指令速度和速度向量；旧存档按默认值读取。恢复后不擅自恢复自动引导。

## 复用与新增的自主测试能力

复用现有 Vitest、Playwright、`?test=1` 下的 `window.__VOID__`、`snapshot()` 和 `step(seconds)`，没有新增服务、测试后台或依赖。

本轮调整：

- `snapshot()` 的 `schemaVersion` 为 2。仍保留常用顶层字段，新增姿态/前向/角速度、实际速度与指令速度、目标位置/距离/接近速度/航向误差/ETA/制动距离、引导状态与阻挡对象、暂停/输入/鼠标锁定、相机与飞船距离/屏幕投影，以及场景代次、已提交渲染代次/模拟时间、帧数与绘制统计。
- 快照返回数组和记录的副本，不再暴露 `.sim`、`.game` 等可变内部对象。旧测试改用快照断言。
- 复用调试入口新增 `scenario(name)`，并支持开发 URL 的 `scenario` 参数。可用名称：`departure`、`transfer`、`approach`、`high-speed`、`occluded`、`behind`。每个场景均有确定初始状态，报告始终标注来源；进入场景模式后不再写玩家存档。
- `rendering.ready` 表示当前场景和姿态已经提交过一帧渲染；重建场景或直接模拟推进后不能沿用上一帧的 ready。截图还会等待帧号增长。当前场景构建是同步过程，这些字段没有声称新增异步宇宙加载系统，也不代表实体 GPU 性能达标。
- `step(seconds)` 保留给确定性模拟和第一轮着陆/起飞回归，限制输入范围。真实飞行主路径不调用它，也不使用场景定位。
- 接口仅在开发构建并带 `?test=1` 时启用；生产 URL 的同名参数不提供测试接口或场景定位。

## 验证范围

- 保留完整探索循环浏览器回归：驾驶、扫描、着陆、步行采样、鼠标捕获、暂停、登船、起飞、星图、跨星系、日志与存档。
- 新的正常玩家端到端路径：真实出生点 → 右键直接锁定 → 星图选择 PYRA → G → 实际飞越中间空间 → 近空减速抵达 → F 扫描 PYRA → 刷新恢复。没有直接改内部状态或推进模拟时间。连续位置变化还受实际经过的模拟时间及速度上限约束。
- 命名场景检查单独标注：高速状态下持续 W 释放 Shift、X 制动横向运动、前/后半球提示、天体遮挡和手动绕行接管、鼠标锁定后手动接管、高速接近的真实时间减速、场景隔离存档、状态副本不可变更内部对象。
- 逻辑测试覆盖加减速、旋转平滑、不同步长结果、渐进导航、接管、实际跨空间移动、接近制动、遮挡、射线锁定、屏外投影、存档兼容和场景确定性。

## 仍存在的差距

本轮没有进行全面渲染升级，也没有增加星系、地表内容或独立测试平台。仍使用压缩尺度与辅助飞行物理；远航是对所选行星的直线引导，遇到遮挡需要玩家先绕行，尚无自动多段路线规划。ETA 依当前速度估算，会随转向和减速变化。

云端 Chromium 使用软件渲染。测试能证明输入、状态和画面在这些路径上相符，不能代替 Windows/macOS 的实体 GPU、Safari/Firefox、持续长时间游戏以及所有任意姿态/障碍组合的验证。

线上地址仍为 [第一轮试玩](https://mkc-mankii.github.io/void-explorer/)，尚不反映本轮变化。所有新成果在当前云端仓库和本地分支中，供审查后再决定推送和发布。
